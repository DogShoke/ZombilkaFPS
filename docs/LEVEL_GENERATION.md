# Офисная арена из модульных ячеек — первый прототип

Текущий этап: одна Office OpenArena. Остальные схемы временно отключены в обычном Play по решению пользователя. Следующий этаж повторяет ту же сетку с другим сочетанием авторских модулей. Это прототип для оценки боя, а не новая библиотека макросхем.

## Фиксированная сетка

5×5, CellSize=36 studs, пол 180×180.

```text
Z O O O Z
O C O C O
O O L O O
O C O E O
Z O S O Z
```

Верх рисунка — север/отрицательный Z; вход снизу. Центры ячеек по X/Z: −72, −36, 0, 36, 72. Роли и координаты никогда не перемешиваются.

| Роль | Модуль |
| --- | --- |
| OPEN | Пустой проход или плоская отделка пола; препятствий нет. |
| COVER | Остров рабочих мест, ресепшен, серверная группа, зона отдыха/обслуживания. |
| HARD_COVER | Архивный или серверный блок; доступны в библиотеке, в этой исходной сетке H отсутствует. |
| ELEVATED | Рабочая площадка 16×10, высота 6; два пандуса шириной 16 и длиной 10. Вся структура 16×30 внутри ячейки. |
| LANDMARK | Центральный ресепшен с табличкой; два согласованных варианта. |
| START | Свободная площадка у лифта; кабина остаётся в южной части той же ячейки. |
| SPAWN_EDGE | Свободный угловой подход, иногда с декоративными трещинами. |

## Где менять модули

- `src/server/OfficeTiles.luau`: библиотека вариантов. Каждый содержит Id, Width/Depth, Purpose, Class и фиксированный список Slots.
- `src/server/FloorLayout.luau`: строки сетки, выбор целого варианта по seed, позиции движения и появления. Никакой отдельной случайной расстановки предметов.
- `src/server/OfficeMap.luau`: сборка выбранных модулей, пола, подъёма, света и лифта.
- `src/server/FloorGeometry.luau`: проверка настоящих границ моделей, коллизий, видимости и путей Roblox.
- `src/shared/Config.luau`: GridSize=5, CellSize=36, Version=5, общие ограничения.
- `src/server/ArenaAssets.luau`: исходные модели, текстура, единый масштаб3.5, правильные pivots и простые невидимые коллайдеры.

Слот: `{"OfficeDesk", localX, localZ, yawDegrees, collision, optionalBaseY}`. Координаты и повороты заданы вручную. Размеры мешей не меняются от seed. Выбирается весь законченный модуль, а не случайный набор предметов. Обычный модуль занимает максимум24×24: по6studs свободно от каждой стороны ячейки, между соседними группами минимум12. У подъёма остаются широкие боковые обходы; концы пандусов подходят ближе к северной/южной границе, где соседние OPEN ячейки свободны.

`Workspace.OfficeRun.Floor001.Props.Tile_4_4` — пример папки конкретной ячейки. Атрибуты Role/Module/Row/Column позволяют понять, что выбрано. Все25 ячеек представлены папками, включая пустые.

## Бой

Для этого этапа цель — существующая квота убийств. HordeDirector, боевой директор, появление из земли, статистика врагов, оружие и движение не перерабатываются. Четыре Z-ячейки предоставляют зоны появления; существующий спавнер продолжает проверять дистанцию, свободное место, путь, предупреждение и общий лимит. Уничтожаемых кофейных источников в этом прототипе нет.

После квоты работает прежний лифт. Оставшиеся враги остаются опасны. Выбор оружия перед боем сохранён. Рост квоты и характеристик на повторных этажах использует прежний Config.

## Приёмка

Проверяется точная сетка и25 ролей, фактические габариты моделей внутри ячейки, широкие края, коллизия значимых предметов, свободный вход и видимость ресепшена. Roblox Pathfinding проверяет каждый OPEN центр, все4 источника к входу/подъёму, основной маршрут, оба обхода, поперечные связи и оба пандуса. Широкие маршруты проверяются агентом радиуса5.

Две попытки меняют только варианты модулей. Третья выбирает фиксированные первые варианты, с той же топологией и полноценной проверкой. При полном отказе этаж не принимается. Предел700частей/12секунд проверки сохранён.

`tests/OfficeTiles.luau` проверяет детерминизм и несколько сочетаний. `tests/PhysicalOfficeTiles.luau` проверяет настоящую ходьбу игрока, коллизии, обход ресепшена и подъём NPC без прыжков. Для ввода игрока нужен временный клиентский драйвер; тесты не входят в Rojo. Старые проверки v4 перемещены в tests/legacy, их результаты исторические.

Актуальные наблюдения: tests/results/OfficeTilesQA.json и AI/IMPLEMENTATION.md. Успешные пути и коллизии доказывают техническую проходимость; удовольствие от боя и качество компоновки оцениваются обычной игрой. Автоматического коммита нет.
