# Как сейчас генерируются этажи

Описание текущей реализации на 2026-10-05. Здесь приведено поведение существующего кода, а возможные доработки выделены отдельно.

## Кратко

Каждый этаж — прямоугольная площадка **264 × 288 studs** с центральным проходом и комнатами по сторонам. Генератор выбирает одну из четырёх тем, наполнение комнат, объединение соседних ячеек, перегородки, цветовой акцент и иногда верхнюю галерею с двумя лестницами.

Основная сетка, положение лифта и способы расстановки мебели сейчас фиксированы. Поэтому этажи отличаются наполнением, но их общий каркас остаётся узнаваемым. Произвольного графа коридоров, случайных входов/выходов и набора заранее смоделированных комнат пока нет.

Номера этажей растут без заданного игрового предела. В мире хранятся только текущий этаж и, после зачистки, подготовленный следующий. Это не башня, в которой постепенно накапливаются все пройденные этажи.

## Какие файлы за что отвечают

| Файл | Назначение |
| --- | --- |

Код меняй в этих файлах на диске: Rojo — источник истины. Изменения ModuleScript во время Play могут не подхватиться из-за кеширования `require`; для проверки останови и заново запусти игру.

## Seed и выбор темы

`OfficeMap.Build()` выбирает seed забега:

```luau
runSeed = Random.new():NextInteger(1, 2000000000)
```

Для этажа с номером `number` вычисляется собственный seed:

```luau
seed = (runSeed + number * 104729) % 2147483647
```

`Random.new(seed)` определяет планировку. При одинаковых seed забега, номере этажа, коде и настройках получится одинаковое описание. Изменение порядка случайных вызовов тоже меняет результат.

Темы из `Config.Run.Generation.Themes` перемешиваются с помощью отдельного `Random.new(runSeed)`. Затем этажи проходят этот список по кругу. Сейчас тем четыре: `Office`, `Laboratory`, `Warehouse`, `Parking`; в каждом блоке из четырёх этажей встречаются все темы в одном и том же для этого забега порядке.

Это не независимый случайный выбор темы на каждом этаже. Соседние этажи при текущем списке имеют разные темы; пятый повторяет тему первого, но получает другой seed планировки.

Поле `Signature` имеет вид `Theme:seed`. Оно удобно для диагностики, но разные подписи не гарантируют визуально уникальную геометрию. Случайный выбор зомби и точек их появления использует отдельный генератор и не воспроизводится только по seed карты.

## Сетка комнат

`FloorLayout.Generate()` перебирает координаты ячеек `x = -2..2`, `z = -2..2`, пропуская весь столбец `x = 0`. Это даёт **20 возможных ячеек** под комнаты.

Условный вид сверху, без мебели и галереи:

```text
                  X
           -2  -1   0  +1  +2
Z = -2      К   К   │   К   К
Z = -1      К   К   │   К   К
Z =  0      К   К   │   К   К
Z = +1      К   К   │   К   К
Z = +2      К   К   │   К   К
                    │
                  ЛИФТ  (+Z)

К — возможная ячейка комнаты; │ — центральный проход.
Соседние К вдоль Z могут объединиться в одну длинную комнату.
```

При текущих значениях:

- `CellSize = 48`: центры комнат по X — −96, −48, +48, +96; по Z — −96, −48, 0, +48, +96.
- `RoomSize = 36`: обычная комната 36 × 36, номинальный промежуток между соседними комнатами — 12 studs.
- Центральный столбец свободен от комнат. Поперечные промежутки и внешний обход дают альтернативные маршруты.
- Декоративная дорожка в центре имеет ширину 20 и длину 240; она не ограничивает физическую ширину прохода.

### Объединение ячеек

Для свободной ячейки генератор с вероятностью **30%** пробует занять следующую по `+Z`. Объединение разрешено, если следующая ячейка существует, свободна и не зарезервирована под галерею.

Получается комната шириной 36 и глубиной `36 + 48 = 84`, центр которой смещён на 24 studs по Z. Занятые ячейки больше не обрабатываются. Объединение происходит только попарно, только вдоль Z; по X и в цепочки из трёх ячеек комнаты не объединяются.

Без галереи число комнат не превышает 20, а с галереей — 14: фактическое число ниже из-за объединений.

### Данные одной комнаты

```luau
{
    X = ..., Z = ...,        -- Центр относительно начала этажа
    Width = 36, Depth = ..., -- 36 или 84 при текущих настройках
    Kind = "Workstations",  -- Вид мебели
    Enclosed = true,         -- Строить перегородки
    Glass = false,           -- Стеклянные перегородки
    Variant = 1,             -- Случайное число от 1 до 4
}
```

В офисах, лабораториях и складах `Enclosed` включается с вероятностью **72%**. В паркинге перегородок комнат нет. У закрытой комнаты на каждой из четырёх сторон оставляется центральный проём шириной **14**, высота перегородок **8**. Это открытые проёмы без дверных створок.

В лаборатории перегородки всегда стеклянные. В остальных темах `Glass` выбирается с вероятностью **30%**; если комната открытая, это поле не влияет на её стены.

## Темы и мебель

Тип комнаты выбирается равновероятно из списка. Повторяющиеся элементы списка повышают вероятность соответствующего типа.

| Тема | Список типов | Что строит `furnish()` |
| --- | --- | --- |
| Office | Workstations, Meeting, BreakRoom, Archive | Рабочие столы с мониторами и стульями; переговорный стол и экран; стойка, автомат и скамья; архивные шкафы. |
| Laboratory | Lab, Lab, ServerRoom, Storage | Лабораторные столы с образцами; серверные стойки; ящики. Вероятность Lab — 50%. |
| Warehouse | Storage, Storage, Workshop, Archive | Ряды ящиков, низкие технические блоки или архивные шкафы. Вероятность Storage — 50%. |
| Parking | ParkingBay, ParkingBay, Workshop, Storage | По две машины с разметкой либо техническая/складская зона. Вероятность ParkingBay — 50%. |

Расстановка внутри каждого типа написана вручную в `OfficeMap.furnish()`. Большинство предметов стоят по сторонам комнаты, оставляя центральные оси дверей свободными. В длинной рабочей комнате добавляется вторая пара столов; в лабораториях, серверных и складах число повторяющихся предметов зависит от глубины комнаты.

`Variant = 1..4` пока не означает четыре полностью разные композиции. Он влияет, например, на разворот/цвет машин и высоту складских ящиков, но многие типы комнаты его вообще не используют. Чтобы получить заметно разные интерьеры, здесь можно добавить несколько настоящих вариантов расстановки.

Цветовой акцент выбирается из четырёх цветов: бирюзового, синего, охристого и фиолетового. У офиса пол ковровый, у остальных тем — бетонный. Стены паркинга металлические; у остальных тем боковые стены стеклянные. В офисах дополнительно появляются растения вдоль центральной зоны.

Основная мебель создаётся из обычных Roblox Parts. Стулья берутся из существующего `OfficeChairAsset`. Декоративные детали имеют `CanCollide = false` и `CanQuery = false`; основные столы, шкафы, машины и стены участвуют в столкновениях. Если добавлять новые предметы, их коллизии могут перекрыть маршрут даже при доступной на вид комнате.

## Верхняя галерея

Правила появления:

- Этаж 1 — всегда без галереи.
- Этаж 2 — всегда с галереей.
- Начиная с этажа 3 — вероятность `UpperChance`, сейчас **40%**.
- Сторона галереи выбирается случайно: левая или правая.

Даже `UpperChance = 0` не отключает галерею на втором этаже: это отдельное условие в `FloorLayout.Generate()`.

Под галерею и её подходы резервируются шесть ячеек: два столбца выбранной половины, строки `z = -1, 0, +1`. На этом месте нижние комнаты не генерируются.

Галерея имеет размеры **72 × 64**, центр по X — `UpperSide * 84`, по Z — 0, высота поверхности — **10**. Это отдельная площадка над частью этажа, а не полный второй этаж.

Два подхода располагаются с противоположных сторон по Z. Каждый поднимается на 10 studs за 48 studs длины, ширина — 14. Для физики и навигации используется гладкий наклонный коллайдер; 24 видимые ступеньки декоративные. Есть ограждения площадки и лестниц.

На галерее лабораторная мебель для темы Laboratory, техническая — для остальных. Добавляются две точки появления зомби и три контрольные точки навигации: нижние подходы и центр площадки.

## Размеры и параметры

Основные значения находятся в `Config.Run.Generation`:

| Параметр | Сейчас | Что меняет |
| --- | --- | --- |
| HalfWidth | 132 | Полуширина площадки по X; полная ширина 264. |
| HalfDepth | 144 | Полуглубина по Z; полная глубина 288. Также от неё считается положение лифта. |
| CellSize | 48 | Расстояние между центрами ячеек. |
| RoomSize | 36 | Размер обычной комнаты; глубина объединённой — RoomSize + CellSize. |
| DoorWidth | 14 | Проёмы в перегородках комнат. |
| CeilingHeight | 28 | Высота наружных стен и потолка. |
| RoomWallHeight | 8 | Высота внутренних перегородок. |
| UpperChance | 0.4 | Вероятность галереи начиная с третьего этажа. |
| UpperHeight | 10 | Высота галереи и подъём лестниц. |
| RampLength | 48 | Горизонтальная длина каждого подъёма. |
| RampWidth | 14 | Ширина подъёма и прохода в ограждении. |
| Themes | Четыре темы | Список для перемешивания и циклического выбора. |

`Config.Run.BaseHeight = 180` и `FloorHeight = 48` задают положение двух физических слотов: поверхность пола на Y = 180 и Y = 228. Номер этажа и номер слота — разные вещи: этаж 3 снова занимает первый слот с новой геометрией.

**Не все размеры параметризованы.** В коде отдельно заданы диапазон сетки `-2..2`, размеры/центр галереи, позиции колонн, внешних точек появления, светильников, растений и смещения мебели внутри комнат. Например, увеличение `HalfWidth` расширит оболочку, но само по себе не добавит комнаты; увеличение `CellSize` раздвинет комнаты, но не переместит галерею и её зарезервированную область согласованно.

Чтобы существенно изменить масштаб или форму, нужно править одновременно `FloorLayout` и `OfficeMap`, затем проверить проходимость. Старое поле `Config.Run.HalfExtent` не управляет размерами этого генератора.

## Когда этаж создаётся и удаляется

1. При старте `OfficeMap.Build()` создаёт `Workspace.OfficeRun`, seed забега и этаж 1 в слоте 1. Также создаются внешний городской фон и освещение.
2. `FloorDirector` ждёт игрока и выбор оружия. До выбора зомби не появляются.
3. После вступления длительностью 4 секунды начинаются три волны. Между волнами — 4 секунды.
4. После убийства всех зомби последней волны создаётся этаж `number + 1` в другом слоте. Через 1 секунду открывается лифт и разрешается переход.
5. Сервер проверяет владельца забега, состояние игры, нахождение живого игрока внутри кабины и завершение волн. Затем закрывает двери за 0.85 секунды и выдерживает 3.5 секунды поездки.
6. Игрок переносится в кабину следующего этажа. Старый этаж удаляется, обновляются точки появления, границы и характеристики зомби. Двери открываются.
7. После выхода из кабины начинается вступление следующего этажа и новый набор волн.

После смерти текущий этаж и seed сохраняются; волны сбрасываются, подготовленный следующий этаж удаляется, игрок снова выбирает оружие. При уходе владельца забег сбрасывается на этаж 1 с тем же seed. Новый запуск сервера создаёт новый seed. Текущий директор ориентирован на одного владельца забега; полноценного совместного прохождения в нём нет.

В модели `FloorXXX` находятся `Geometry`, `Props`, `ZombieSpawns`, `ElevatorLobby` и `PlayerSpawn`. Атрибуты модели включают `FloorNumber`, `Seed`, `Theme`, `ThemeLabel`, `Levels`, `Signature`, `RoomCount`.

`ReplicatedStorage.RunState` публикует состояние прохождения: `Floor`, `LayoutIndex` (физический слот), `Theme` (русская подпись), `RunSeed`, `Seed`, `Levels`, `Wave`, `Waves`, `WaveBudget`, `Alive`, `Remaining` и другие служебные атрибуты.

## Где появляются зомби

`OfficeMap` собирает кандидатов: центр каждой комнаты, девять дополнительных точек в центральной и внешних зонах, ещё две точки на галерее при её наличии. Они видны в структуре как невидимые `ZombieSpawns.Zone...`.

Перед появлением `ZombieService` пробует по три случайных смещения до ±3 studs по X/Z возле каждого кандидата и отбрасывает точки:

- ближе 32 studs к любому живому игроку;
- дальше 360 studs от ближайшего живого игрока;
- внутри мешающего коллайдера карты, по проверке области 3.3 × 4 × 3.3;
- ближе 8 studs к уже существующему зомби.

Среди допустимых точек выбирается лучший случайный балл со штрафом за появление перед направлением взгляда головы игрока. Это предпочтение, а не гарантия появления вне экрана или за стеной. Если точки нет либо достигнут лимит живых зомби, попытка не расходует бюджет волны; следующая попытка происходит через `SpawnInterval = 1.15` секунды.

Границы перемещения зомби задаются по текущей карте: половина ширины и глубины минус 3 studs. Для перехода между высотами AI использует Roblox Pathfinding. Новый интерьер должен оставлять место для агента с радиусом 2 и высотой 5.

## Как растёт сложность

Пусть `extra = number - 1`. Значения берутся из `Config.Run.Difficulty` и базовых настроек `Config.Zombies`:

| Показатель | Формула сейчас |
| --- | --- |
| Бюджет каждой волны | Базовое значение из `{5, 7, 9}` + `min(extra * 2, 18)` |
| Максимум одновременно живых | `min(9 + floor(extra / 3), 16)` |
| Здоровье | `min(100 + extra * 4, 100 * 1.8)` |
| Скорость | `min(11 + extra * 0.1, 14)` |
| Урон атаки | `min(12 + extra * 0.6, 24)` |

Например, на этаже 1 волны содержат 5/7/9 зомби, на этаже 2 — 7/9/11, а с этажа 10 — 23/25/27. Бюджет волны — общее число зомби, не число одновременно живых. У каждого показателя свой момент достижения предела. Геометрия не становится сложнее от номера этажа, кроме правила галереи на первых двух этажах.

## С чего начать изменения

| Что хочется изменить | Где менять |
| --- | --- |
| Чаще или реже видеть галерею | `Config.Run.Generation.UpperChance`; для второго этажа — отдельное условие `upper` в `FloorLayout`. |
| Более открытые комнаты | Вероятность `.72` в выборе `Enclosed` внутри `FloorLayout.Generate()`. |
| Больше длинных комнат | Вероятность `.3` в вычислении `merge` там же. |
| Иное соотношение типов комнат | Списки `kinds` в `FloorLayout`; повторы задают вес выбора. |
| Разные композиции одного типа | `OfficeMap.furnish()`, с использованием `room.Variant`. |
| Другие цвета, свет и материалы | Таблицы `C`, `accents`, а также `buildFloor()` и `Build()` в `OfficeMap`. |
| Больше комнат/другой рисунок проходов | Циклы сетки и правила резервирования в `FloorLayout`, согласованная геометрия в `OfficeMap`. |
| Новая тема | `Themes` в Config, `labels` и списки `kinds` в FloorLayout, `roomLabels`/`furnish()` и тематические условия в OfficeMap. Одного нового имени в Config недостаточно. |
| Больше или сильнее зомби | `Run.Waves`, `Run.Difficulty`, базовые значения `Zombies` в Config. |

Для заметно более интересных маршрутов следующий шаг — описывать связи комнат и проходов явно, выбирать несколько схем расположения, менять позиции входа/лифта и использовать несколько вариантов мебели с сохранением свободных путей. **Это возможное развитие; сейчас такой логики нет.**

## Как воспроизвести и проверить этаж

В серверной Command Bar Studio во время теста можно получить описание без создания геометрии:

```luau
local Layout = require(game.ServerScriptService.Server.FloorLayout)
local layout = Layout.Generate(123456, 3)
print(game:GetService("HttpService"):JSONEncode(layout))
```

Чтобы записать seed текущего забега:

```luau
local state = game.ReplicatedStorage:FindFirstChild("RunState")
if state then
    print(state:GetAttribute("RunSeed"), state:GetAttribute("Floor"))
end
```

Подставь эти два значения в `Layout.Generate()` для повторения планировки. Сама эта функция не создаёт Parts; построение выполняет `OfficeMap.CreateFloor(map, number, slot)`.

После изменений запускай [tests/ProceduralFloors.luau](../tests/ProceduralFloors.luau) в серверном контексте Studio, пока забег не активен. Тест проверяет 200 повторяемых описаний для seed 123456, затем строит четыре тематических этажа в отдельном временном слоте и проверяет пути от входа до центров комнат, подходов и галереи. Временные объекты удаляются после проверки. Для другой выборки поменяй seed и диапазон номеров в тесте.

Для исходного генератора ранее в Studio проверены 200 повторяемых описаний, все 60 контрольных путей четырёх тематических этажей, подъём игрока по обеим лестницам, подъём/атака зомби на галерее и пять последовательных переходов лифта. Наблюдения записаны в [AI/IMPLEMENTATION.md](../AI/IMPLEMENTATION.md).

Эта выборка не доказывает проходимость любой будущей карты. В обычной игре генератор **не запускает проверку всех путей и не пересоздаёт неудачные этажи автоматически**. После правки сетки, размеров или коллизий проверь несколько seed, пройди карту игроком, дождись подъёма зомби на галерею и проверь переход лифта и сброс после смерти.
